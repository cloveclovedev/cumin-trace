# ダッシュボード

要件の全体像と、要件 → 要求Issue → 実装Issue の進捗を、1ページで見るための要件を定める。

## 全体像

ダッシュボードは、サイトの中の1ページである。上から、GitHub を読んだ時刻、要件の進捗、不整合、要件の一覧の順に並ぶ。マイルストーンは、要件文書ではなく、要求Issueに付いているものを使う。

![ダッシュボードの画面](dashboard-wireframe.svg)

図の元ファイル: [dashboard-wireframe.puml](dashboard-wireframe.puml)

ダッシュボードは静的なページで、サイトをビルドするときに作られる。表示されるのは、最後に GitHub を読んだ時点の状態である。

![ダッシュボードが更新される流れ](dashboard-update.svg)

図の元ファイル: [dashboard-update.puml](dashboard-update.puml)

## 要件

### `CTR-DASH-001` 要件の一覧と進捗

要件を、カテゴリ、要件、子要件の階層のまま一覧で表示する。要件ごとに、進捗、対応する要求Issueとそのマイルストーン、実装Issueの数 (閉じた数 / 全体の数) を示す。廃止した要件は表示しない。変更後の未起票 (`CTR-TRC-010`) は、ほかの未起票と見分けられるように示す。

- 検証: `demo` この文書群の要件で確かめる

---

### `CTR-DASH-002` マイルストーンごとの集計

ページの先頭に、集計を表示する。未起票の要件の数と、要求Issueのマイルストーンごとの、進行中と完了の要件の数を示す。マイルストーンのない要求Issueに対応する要件も、1つの行として集計する。

- 検証: `demo` 集計の数が、要件の一覧の表示と一致する
- 状態: 廃止

---

### `CTR-DASH-003` 次に起票する要件

未起票の要件を、一覧で表示する。Maintainer が次に要求Issueを書くときの出発点になる。この一覧が空であれば、要件文書に書いたことは、すべて要求Issueになっている。

- 検証: `demo` 要求Issueのない要件が一覧に出て、要求Issueを書くと一覧から消える
- 状態: 廃止

---

### `CTR-DASH-004` 絞り込み

マイルストーンと進捗で、要件の一覧を絞り込める。

- 検証: `demo` マイルストーンを v0.1、進捗を進行中にして、該当する要件だけが残る
- 状態: 廃止

---

### `CTR-DASH-005` リンク

要件からは、サイトの中のその要件へリンクする。要求Issueと実装Issueからは、GitHub のそのIssueへリンクする。

- 検証: `demo` それぞれのリンクをクリックして、移動先を確かめる

---

### `CTR-DASH-006` 読んだ時刻の表示

GitHub を読んだ時刻を表示する。GitHub を読めなかったときは、要件の一覧も進捗も表示せず、GitHub を読めなかったことだけを表示する。

- 検証: `demo` token を設定せずにビルドし、ダッシュボードには GitHub を読めなかったことだけが表示され、文書のページは表示される

---

### `CTR-DASH-007` 静的なページ

ダッシュボードは静的なページとして作る。表示のためのサーバは持たない。

- 検証: `inspection` ビルドの出力がファイルだけである

---

### `CTR-DASH-008` 自動での更新

cumin-trace は、main への push と定期実行でサイトをビルドし直す GitHub Actions の workflow の例を提供する。ビルドしたサイトをどこに置くかは、例に含めない。

- 検証: `inspection` workflow の例を読んで確かめる

---

### `CTR-DASH-009` 不整合の表示

対応づけで見つかった不整合 (`CTR-TRC-006`) を、一覧で表示する。不整合ごとに、種類、要求Issue、IDを示す。不整合がなければ、一覧は表示しない。

- 検証: `demo` 要件文書にないIDを書いた要求Issueが一覧に出て、その要求Issueを直すと一覧から消える
