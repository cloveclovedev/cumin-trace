# 要件文書の書式

製品リポジトリの要件文書を、人にも道具にも読める形にするための決まり。この文書自身も、この書式で書いてある。

## 考え方

- 1つのIDは、真偽を確かめられる1つの決まりである。受け入れの確認の1行と同じ粒度にする
- IDを持たない文章 (背景、理由、図、例) は、自由に書く。道具は読まない
- 要件の状態は増やさない。mainにある要件は有効である。下書きは、mergeされる前のブランチにある。あるのは「廃止」だけである
- 進み具合は書かない。GitHubから導く ([道具の要件](tool.md) の「対応づけ」)

## 要件の2つの形

見出しの形。理由や例を添えたい要件に使う。

```markdown
### PC-TASK-003 証拠の出し直しは期日前にN回まで

タスク実行者は、期日前に限り、証拠を最大N回出し直せる。Nの既定値は1。

- 検証: test。N+1回目の出し直しが拒否される
- 対象: v0.1
```

表の形。短い決まりが並ぶところに使う。

```markdown
| ID | 要件 | 検証 | 対象 |
|---|---|---|---|
| PC-TASK-004 | 催促メッセージは、期日前だけ送れる | test。期日後の送信が拒否される | v0.1 |
```

## IDと欄

| ID | 要件 | 検証 | 対象 |
|---|---|---|---|
| CTR-FMT-001 | 要件文書は、製品リポジトリの設定に書いたディレクトリ (初期値は `docs/ja/requirements/`) の下の Markdown である。frontmatter がなくても読める | test。frontmatter のない文書から要件を読める | v0.1 |
| CTR-FMT-002 | IDの形は `<製品>-<領域>-<連番>` である。製品と領域は英大文字と数字で、連番は3桁である。子の要件は、親のIDに `.<番号>` を足す (例: `PC-TASK-003.1`) | test。形に合わないIDを誤りにする | v0.1 |
| CTR-FMT-003 | IDを書ける場所は2つである。見出しの先頭と、列名が `ID` の表の列である。ほかの場所に書いた、その製品の接頭辞のIDは、その要件への参照である。コードブロックの中と、ほかの製品の接頭辞のIDは読まない | test。2つの形から同じ要件が読める。本文の中のIDは参照になる。コードブロックの中のIDは無視される | v0.1 |
| CTR-FMT-004 | 要件の欄は `検証`、`対象`、`状態` の3つである。見出しの形では `- 検証: ...` の箇条書きに、表の形では同じ名前の列に書く | test。2つの形から同じ欄が読める | v0.1 |
| CTR-FMT-005 | `検証` は、`test`、`demo`、`inspection`、`analysis` のどれかで始める。そのあとに、確かめ方を1文で書く | test。4語のほかで始まる検証を誤りにする | v0.1 |
| CTR-FMT-006 | 子を持たない要件には、`検証` が必須である。子を持つ要件は、子の検証で確かめるので、書かなくてよい | test。検証のない葉の要件を誤りにする | v0.1 |
| CTR-FMT-007 | `対象` には、その要件を入れる版を書く (例: `v0.1`)。書かなければ、対象は未定である | test。対象のない要件が、未定として読める | v0.1 |
| CTR-FMT-008 | `状態` に書けるのは `廃止` だけである。置き換えた要件があれば `廃止。<ID> に置き換え` と書く。廃止した要件は消さずに残す | test。廃止と置き換え先が読める | v0.1 |
| CTR-FMT-009 | 番号は使い回さない。要件を別の領域に移すときは、元を廃止にして、新しいIDを振る | inspection。Pull Requestのレビューで確かめる。道具による検出は [backlog](backlog.md) にある | v0.1 |
| CTR-FMT-010 | 子の要件は、親と同じ文書に書く | test。親が別の文書にある子を誤りにする | v0.1 |
| CTR-FMT-011 | 製品の接頭辞と、使ってよい領域の名前は、製品リポジトリの設定ファイル (TOML) に書く | test。設定にない領域のIDを誤りにする | v0.1 |

4つの検証の方法は、次のように使い分ける。

| 方法 | 意味 | 例 |
|---|---|---|
| `test` | 自動テストで確かめる | 上位要件のテスト |
| `demo` | 人かAgentが、動かして確かめる | live scenario、画面の操作 |
| `inspection` | 文書、設定、コードを読んで確かめる | 権限の表、レビュー |
| `analysis` | 計算や調査で確かめる | 費用の見積もり、規約の確認 |
