# cumin-trace 要求仕様書

## 解決したい課題

製品を進めるときに一番難しいのは、次の3つを同時に保つことである。

1. 要件文書の全体を把握している
2. 要件のうち、どこまで実現できているかが分かる
3. まだ実現していない要件を、漏れなく、適切な大きさの要求Issueにする

cumin-works には、要求Issueから下の対応づけ (要求Issue → 実装Issue → Pull Request → 受け入れ) が既にある。切れているのは、要件文書の行から要求Issueへの1本である。要件文書が大きくなると、この1本を目で追えなくなる。

## 目的

Maintainerが母国語で書いた要件文書を正本にしたまま、要件の全体像と、要件 → 要求Issue → 実装Issue の進み具合を、少ない認知負荷で見られるようにする。

## 指標

- 「対象の版の要件のうち、まだ要求Issueになっていないもの」を、1ページを開くだけで答えられる
- 新しい製品の要件文書を、雛形から書き始められる。書式を考える時間が要らない

## 位置づけ

- cumin-works 本体の外の道具である。本体との結合点はGitHubだけである (要求Issueのラベルと sub-issue)。cumin-works を使わないリポジトリでも動く
- 要件文書の管理の仕方は人によって違う。この道具は、まずMaintainer自身の管理の仕方に合わせて作る。保守運用の支援の一部として、追加の機能として渡せる形にしておく
- このリポジトリは private である

## 登場人物

- Maintainer: 要件文書を書き、要求Issueを書く人。cumin-works の Maintainer と同じ
- Agent: Maintainerと一緒に要件文書を書く、Claude Code などのAI
- 製品リポジトリ: 要件文書を持つリポジトリ。finance-v2、cumin-works、peppercheck-next など
- 道具: このリポジトリが提供するコマンド、雛形、skill、サイトの雛形

## 全体の構成

![全体の構成](overview.svg)

図の元ファイル: [overview.puml](overview.puml)

- 正本は、製品リポジトリの `docs/ja/requirements/` の Markdown である。日本語で書く。英語版を手で維持しない
- 要件の構造化したデータ (`requirements.json`) は生成物である。人は編集しない
- 進み具合は文書に書かない。道具がGitHubを読んで導く
- 公開したくない内容は、言語ではなく機密性で分ける。価格や事業の戦略は別のprivateなリポジトリに書き、製品の要件は製品リポジトリに書く

## 決めたこと

2026-10-11に決めた。

| 論点 | 決めたこと | 理由 |
|---|---|---|
| 要件文書の置き場所 | 製品リポジトリの中 | Agentがworktreeから読める。要件の変更とコードの変更が同じ履歴に並ぶ。cumin-works の保護されたパスが効く |
| 言語 | 日本語が正本 | 書く速さと、考える速さを優先する。英語の読み手には、英語の要求Issueがある |
| サイトの単位 | 製品ごとに1つ | 公開とprivateを、製品ごとに選べる |
| SysML v2 | 語彙だけを借りる。記法とパーサは使わない | 要件の木 (contain)、要件を満たすIssue (satisfy)、要件を確かめるテスト (verify) の3つの関係で足りる。SysML v2 の仕様書は確かめていない。採り入れを広げるときに確かめる |
| 図 | 手で描く図はPlantUMLだけ | cumin-works と同じ流儀にする。要件の木と進み具合の表示は、道具が生成する |
| ダッシュボード | サイトの中の静的なページ | サーバを持たない。操作の入口が要るようになったら見直す ([backlog](backlog.md)) |
| 技術 | Go のコマンド、GitHub Actions、Astro + Starlight | Go は cumin-works と同じ。Starlight は、全てのページに frontmatter の `title` を求める (公式文書の Frontmatter Reference で確認)。文書を書き換えずに済むよう、道具が補う |

## 名前

- 製品の名前は cumin-trace である。trace は、要件から実装までをたどれること (requirements traceability) を指す
- コマンドの名前は `cumin-trace` である
- 製品リポジトリに置く設定ファイルの名前は `.cumin-trace.toml` である
