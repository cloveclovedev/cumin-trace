# タイトルと本文の読み方

[構造化データの出力の設計](index.md) の細部。要件の見出し、要件の範囲、フィールドの見分け方は、[要件文書の読み方](../check/reading.md) のとおりである。ここでは、それに足すことだけを決める。

## 要件のモデルに足すもの

`internal/requirement/domain.go` の `Requirement` に、次の2つを足す。これで、`CTR-EXP-001` が挙げる値のすべてをモデルが持つ。

| 値 (`CTR-EXP-001`) | フィールド | 型 | 中身 |
|---|---|---|---|
| タイトル | `Title` | `string` | [タイトル](#タイトル) |
| 本文 | `Text` | `string` | [本文](#本文) |

- 読むのは `internal/requirement/markdown.go` の `readDocument` である。要件の見出しを見つけたときにタイトルを、走査の終わりに本文を決める。
- IDの形式が正しくない要件の見出しは、モデルにならないので、タイトルも本文も読まない。
- 書式検査は `Title` と `Text` を使わない。書式検査の結果は変わらない。

## タイトル

タイトルは、見出しの内容のうち、最初のコードスパンより後ろを、書いたままの Markdown で持つ (`CTR-FMT-003`)。

1. 見出しの内容は、goldmark の `Heading.Lines()` の行である。`#` の見出しでは、行頭の `#` と、行末の閉じる `#` の並びを含まない。下線 (`===`、`---`) の見出しでは、下線の行を含まない。
2. 見出しの内容の先頭は、バッククォートの並びである。同じ長さで、前後にバッククォートがない次の並びが、コードスパンの終わりである。この規則は CommonMark のコードスパンと同じである。
3. コードスパンの終わりより後ろの文字を、前後の空白とタブを除いて、タイトルにする。
4. 下線の見出しの内容が2行以上のときは、行ごとに前後の空白を除き、空白1つでつないでから 3 を行う。

例:

| 見出し | タイトル |
|---|---|
| ``### `CTR-EXP-001` 出力する内容`` | `出力する内容` |
| ``## `CTR-EXP-001` 出力する内容 ##`` | `出力する内容` |
| ``### `CTR-EXP-001` *強調* と \* の文字`` | `*強調* と \* の文字` (書いたまま) |
| ``### `CTR-EXP-001` `` | 空の文字 |

- 強調、リンク、バックスラッシュのエスケープは、書いたままにする。サイトが Markdown として表示するためである。
- タイトルが空でも、エラーにしない。書式検査が、空のタイトルをエラーにしないためである ([エラーと出力](../check/errors.md))。JSON には空の文字を書く。

## 本文

本文は、要件の見出しの次の行から、最初の止まる行の前までの行を、書いたままつないだものである。

```text
### `PC-TASK-003` 見出し        <- 見出し (本文に入らない)
本文の1行目                      <- 本文の始まり
本文の2行目
- 検証: `test` ...               <- 止まる行 (フィールド)
---
```

### 始まり

本文は、要件の見出しの最後の行の、次の行から始まる。下線の見出しでは、下線の行が見出しの最後の行である。

### 終わり

見出しより後ろにある、文書の最上位のブロックを順に見る。最初に来た、次のどれかの最初の行が、止まる行である。どれもなければ、ファイルの終わりまでが本文である。

| 止まる行 | 例 | 理由 |
|---|---|---|
| 文書の最上位の見出し。レベルも、要件の見出しかどうかも問わない | 子要件の見出し、次の要件の見出し、カテゴリの見出し | 見出しは、見た目でも区切りである。子を持つ要件の本文は、子要件の見出しで終わる |
| 文書の最上位の区切り線 | `---` | 要件の終わりの印である |
| 文書の最上位の、番号なしの箇条書きの、フィールドの項目 (`検証` か `状態`) | `- 検証: ...` | 本文の後ろに、フィールドを書く (`CTR-FMT-005`) |

- 止まる行は、構文木で決める。コードブロック、引用、入れ子の箇条書きの中の `#`、`---`、`- 検証:` は、止まる行ではない。
- フィールドの項目の見分け方は、`readFields` と同じである。同じ箇条書きで、フィールドより前にあるほかの名前の項目は、本文に入る。
- ブロックの最初の行は、そのブロックの `Pos()` (ブロックが始まるバイトの位置) から、`lineAt` で求める。フィールドでは、箇条書き (`List`) ではなく、フィールドの項目 (`ListItem`) の `Pos()` を使う。そうしないと、フィールドより前の項目が本文から落ちる。
- 空行を挟まずに段落の次の行に書いた `---` は、CommonMark では区切り線ではなく、下線の見出し (レベル 2) になる。その段落の行は見出しなので、本文はその前で終わる。書式検査も同じ構文木を読むので、2つは食い違わない。
- 止まる行より後ろの文は、本文に入らない。`検証` の行の後ろに書いた段落も入らない。

### 文字

- 行は、ソースの文字を書いたまま使う。Markdown を文字に変えない。行末の `\r` は除く。
- 行を `\n` でつなぐ。先頭と末尾の空行 (空白だけの行を含む) を除く。最後に改行を付けない。
- 本文の行がないときは、空の文字にする。子を持つ要件で、見出しのすぐ後ろに子要件の見出しがあるときが、これにあたる。
- frontmatter は、要件の見出しより前にしかないので、本文に入らない。
